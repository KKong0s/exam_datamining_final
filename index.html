คำความหมายชื่อเรียกอื่น
True Positive (TP)ทายว่าใช่ แล้วใช่จริงHit
True Negative (TN)ทายว่าไม่ใช่ แล้วไม่ใช่จริงCorrect Rejection
False Positive (FP)ทายว่าใช่ แต่จริงๆ ไม่ใช่False Alarm, Type I error
False Negative (FN)ทายว่าไม่ใช่ แต่จริงๆ ใช่Miss, Type II error
Condition Positive (P)จำนวนที่ใช่จริงทั้งหมด = TP + FN
Condition Negative (N)จำนวนที่ไม่ใช่จริงทั้งหมด = FP + TN

ทริคจำ คำหน้า (True/False) บอกว่าทายถูกหรือผิด คำหลัง (Positive/Negative) บอกว่าโมเดลทายว่าอะไร เช่น FN คือทายว่า Negative และทายผิด ในสไลด์ หมา = Positive, แมว = Negative ดังนั้นแมวที่ถูกทายว่าหมาคือ FP

ตัววัด 4 ตัวหลัก

PrecisionTPTP + FPความแม่นยำ แยกทีละคลาส ดูจากผลการทำนาย คือที่ทายว่าใช่ทั้งหมด ถูกกี่ส่วน
RecallTPTP + FNความถูกต้อง แยกทีละคลาส ดูจากผลเฉลย คือของที่ใช่จริง เก็บได้กี่ส่วน
F-measure2 × P × RP + Rค่าเฉลี่ยของ Precision และ Recall จะสูงได้ต่อเมื่อทั้งคู่สูง
AccuracyTP + TNTP + TN + FP + FNความถูกต้องรวมทุกคลาส คือทายถูกกี่ส่วนจากทั้งหมด
  • Precision, Recall และ F-measure คิดแยกทีละคลาส ต้องบอกว่ากำลังพิจารณาคลาสไหน ส่วน Accuracy คิดรวมทุกคลาส
  • ถ้าเปลี่ยนมุมมองไปคลาสอีกฝั่ง บทบาทจะสลับกัน: Precision(คลาสลบ) = TN/(TN+FN), Recall(คลาสลบ) = TN/(TN+FP)
  • กรณีหลายคลาส (เช่น เสือ/ช้าง/แรด): Precision ของคลาส X = ค่าบนเส้นทแยง ÷ ผลรวมแถว Predicted X, Recall = ค่าบนเส้นทแยง ÷ ผลรวมคอลัมน์ Actual X, Accuracy = ผลรวมเส้นทแยง ÷ ผลรวมทั้งตาราง

ลองคำนวณเอง

ค่าเริ่มต้นมาจากตัวอย่างป้ายจราจรในสไลด์ (ป้าย = Positive) เปลี่ยนตัวเลขเพื่อตรวจคำตอบใบงานได้

สไลด์เขียน Recall ของ spam เป็น 7/9 = 77.78% แต่นับจากตารางจริง spam ที่ทายถูกมี 6 แถว (ID 1, 2, 5, 6, 11, 12) ค่าที่ถูกคือ 6/9 = 66.67% และ Precision ของ normal คือ 57.14% (สไลด์เขียน 57.12%)

ตีความค่าให้เป็น

  • Precision สูง หมายถึงถ้าโมเดลบอกว่าใช่ มักจะใช่จริง (FP น้อย) สำคัญเมื่อการเตือนผิดมีต้นทุนสูง เช่น กรอง spam ที่ไม่อยากให้เมลสำคัญหลุดไปถังขยะ
  • Recall สูง หมายถึงเก็บของที่ใช่ได้เกือบครบ (FN น้อย) สำคัญเมื่อการพลาดมีต้นทุนสูง เช่น ตรวจโรค หรือตรวจจับป้ายจราจร
  • Precision กับ Recall มักสวนทางกัน จึงใช้ F-measure รวมเป็นค่าเดียว
  • Accuracy หลอกได้เมื่อข้อมูลไม่สมดุล เช่น มีผู้ป่วย 1% แล้วโมเดลทายว่าไม่ป่วยทุกคน จะได้ Accuracy 99% แต่ Recall ของคลาสป่วยเป็น 0

ลำดับการทำโจทย์ใบงาน

  1. เลือกคลาสที่กำลังพิจารณาเป็น Positive
  2. เทียบ Actual กับ Predicted ทีละแถว แล้วนับลงช่อง TP / FP / FN / TN
  3. เช็คว่า TP + FP + FN + TN เท่ากับจำนวนแถวทั้งหมด
  4. แทนสูตร Precision → Recall → F-measure → Accuracy

  • Gain Ratio (C4.5) แก้ปัญหาที่ Information Gain ชอบ attribute ที่มีค่าเยอะ เช่น ID
  • Gini Index (CART) เป็นอีกตัววัดความไม่บริสุทธิ์ ค่าน้อยหมายถึงบริสุทธิ์
  • Overfitting คือต้นไม้ลึกเกินไป จำข้อมูล train ได้ดีแต่ทำนายข้อมูลใหม่แย่
  • Pruning คือการตัดกิ่งที่ไม่จำเป็นเพื่อลด overfitting มีทั้ง pre-pruning (หยุดก่อนโต) และ post-pruning (ตัดหลังโต)
  • ข้อดี เข้าใจง่าย แปลงเป็นกฎได้ ใช้ได้ทั้งข้อมูลตัวเลขและข้อมูลกลุ่ม · ข้อเสีย overfit ง่าย และข้อมูลเปลี่ยนเล็กน้อยอาจทำให้ต้นไม้เปลี่ยนทั้งต้น
Part.07
Naïve
Bayes

เทคนิคการจำแนกข้อมูลด้วย Naive Bayes

PROBABILITY

อัลกอริทึมจำแนกข้อมูลแบบมีผู้สอน (supervised) ที่ใช้ความน่าจะเป็นตาม Bayes Theorem (Thomas Bayes) คาดเดาสิ่งที่ยังไม่เกิดจากสิ่งที่เคยเกิดขึ้น สร้างง่ายและไม่ซับซ้อน

ความน่าจะเป็นพื้นฐาน

  • ความน่าจะเป็น = จำนวนเหตุการณ์ที่สนใจ ÷ จำนวนเหตุการณ์ที่เป็นไปได้ (ลูกเต๋าออกเลขคู่ = 3/6 = 50%)
  • Conditional probability P(A|B) = P(A ∩ B) / P(B) คือโอกาสที่ A เกิดเมื่อรู้ว่า B เกิดแล้ว
  • Joint probability P(A ∩ B) คือโอกาสที่ A และ B เกิดร่วมกัน
  • ตัวอย่างยา: กล่อง L มี 4 ชิ้น (แคปซูล 2), กล่อง R มี 5 ชิ้น (แคปซูล 4) → P(L) = 4/9, P(Capsule) = 6/9, P(Capsule | L) = 2/4 = 50%, P(Capsule | R) = 4/5 = 80%

Bayes Theorem

P(C|A) = P(A|C) × P(C) / P(A)
ส่วนชื่อความหมาย
P(C|A)Posteriorโอกาสที่ข้อมูลที่มี attribute A จะเป็น class C ซึ่งเป็นสิ่งที่ต้องการรู้
P(A|C)Likelihoodใน training data ที่เป็น class C มี attribute A กี่ส่วน (A = a₁ ∩ a₂ ∩ … ∩ a_M)
P(C)Priorสัดส่วนของ class C ในข้อมูลทั้งหมด (รู้มาก่อน)
P(A)Evidenceเท่ากันทุก class จึงตัดทิ้งได้ตอนเทียบ

ทำไมเรียกว่า “Naive”

เพราะสมมติว่า attribute ทุกตัวเป็นอิสระต่อกันเมื่อรู้ class แล้ว จึงเอาความน่าจะเป็นของแต่ละ attribute มาคูณกันได้เลย ในโลกจริงมักไม่อิสระกันจริง แต่โมเดลก็ยังใช้ได้ดี

P(C|A) ∝ P(a₁|C) × P(a₂|C) × … × P(a_M|C) × P(C)

ขั้นตอนจำแนก (เล่นกอล์ฟ 14 วัน)

  1. หา Prior: P(yes) = 9/14 = 0.64, P(no) = 5/14 = 0.36
  2. หา Likelihood ของทุกค่าแยกตาม class เช่น P(sunny | yes) = 2/9 = 0.22, P(sunny | no) = 3/5 = 0.60
  3. เมื่อมีข้อมูลใหม่ ให้คูณ likelihood ทุกตัว × prior ของแต่ละ class
  4. เลือก class ที่ได้ค่าสูงกว่า
ข้อมูลใหม่: sunny, hot, high, windy = falseผลคูณ
yes: 0.22 × 0.22 × 0.33 × 0.67 × 0.640.0068
no: 0.60 × 0.40 × 0.80 × 0.40 × 0.360.0276
ทำนาย Play = no เพราะ 0.0276 > 0.0068

จุดควรรู้เพิ่ม

  • Zero-frequency: ถ้าค่าใดไม่เคยเกิดใน class นั้น (P(overcast | no) = 0/5) ผลคูณจะเป็น 0 ทั้งก้อน แก้ด้วย Laplace smoothing (บวก 1 ทุกช่อง) ซึ่งเป็นหลักมาตรฐาน ไม่ได้อยู่ในสไลด์
  • การประยุกต์ใช้: Face Recognition, Email Spam Detection, Categorizing News, Sentiment Analysis, Weather Prediction, Medical Diagnosis, Digit Recognition
  • AI Studio: Retrieve → Set Role (Play เป็น label) → Split Data → Naive Bayes → Apply Model → Performance
  • ข้อดี ง่าย เร็ว ใช้ข้อมูลน้อยก็ได้ · ข้อเสีย สมมติฐาน independence ไม่จริงเสมอ และมีปัญหา zero-frequency

หาความสัมพันธ์ของข้อมูลที่เกิดร่วมกันบ่อย (frequent pattern) ใช้ในธุรกิจค้าปลีก เรียกว่าการวิเคราะห์ตะกร้าตลาด (Market Basket Analysis) เช่น คนซื้อผ้าอ้อมมักซื้อเบียร์ด้วย เป็นการเรียนรู้แบบไม่มีผู้สอน

  • Support เทียบกับ transaction ทั้งหมด ส่วน Confidence เทียบกับเฉพาะตะกร้าที่มี LHS
  • Confidence = 100% หมายถึงซื้อ LHS แล้วซื้อ RHS ทุกครั้ง
  • Confidence ไม่สมมาตร: โยเกิร์ต⇒นม = 100% แต่ นม⇒โยเกิร์ต = 75%
  • ค่าขั้นต่ำกำหนดโดยผู้เชี่ยวชาญ (expert user) กฎที่ดีต้องผ่านทั้ง minimum support และ minimum confidence

Apriori (2 ขั้นตอนใหญ่)

  1. หา frequent itemsets ที่ผ่าน minimum support โดยทำวนซ้ำ 2 ขั้นย่อย:
    • Join สร้าง itemset ที่ยาวขึ้นทีละ 1 จากตัวที่ผ่านรอบก่อน
    • Count นับ support แล้วตัดตัวที่ต่ำกว่าเกณฑ์ทิ้ง
  2. สร้าง association rule จาก frequent itemset (≥ 2 items) แล้วคัดด้วย minimum confidence

ที่ต้องใช้ Apriori เพราะร้านจริงมีสินค้าหลายหมื่นชิ้น ทำให้มี itemset ถึง 2N − 1 แบบ คำนวณทุกแบบไม่ไหว Apriori จึงตัดตัวที่ไม่ผ่านเกณฑ์ตั้งแต่ต้น ถ้า itemset หนึ่งไม่ frequent ชุดที่ใหญ่กว่าที่มี itemset นั้นอยู่ก็ไม่ frequent ด้วย
